## 1. 探针与返回体原文

### P1 · `/artcraft/api/status` 无 `dataRoot`

```
GET http://127.0.0.1:3292/artcraft/api/status   -> HTTP 200
body 顶层字段：plugin, version(0.3.1), platform, config{path,found,autoDiscovered}, bins{13 项}, control{4 端口}, jobs, tools
```
**实测：无 `dataRoot` 字段**（返回体长 2292 字节，字段清单已逐项核对）。
调用方 `client.js:9898`：`const artRoot = data && data.dataRoot ? data.dataRoot.path : '';` → 恒为空串，`rootMismatch`（9899 行）恒为 false，界面上的「ArtCraft 数据目录与画布数据根不一致」提醒永远不会触发。

### P2 · `?op=list&rel=projects` 400

```
GET /artcraft/api/fs?op=list&rel=projects        -> HTTP 400（错误的请求）
GET /artcraft/api/fs?op=list&path=D:/data/canvas-data/projects -> HTTP 200
body: {"path":"D:\\data\\canvas-data\\projects","entries":[pmvex3446bnns, 时空邮递员, 画布test, 门缝里的字条]}
```
调用方 `client.js:4484`（readText）、`4485`（file）走的就是 `?rel=` 形状 → 400。

### P3 · 旧契约写入：**不报错，静默错位到 DSH 进程工作目录**（关键发现）

调用方形状（`client.js:4482/4483`）：`POST /artcraft/api/fs?action=write&rel=<enc>`，JSON 体 `{rel, text}`，**不带 base**。

```
POST http://127.0.0.1:3292/artcraft/api/fs?action=write&rel=blk02-probe-old.txt
Content-Type: application/json
body: {"rel":"blk02-probe-old.txt","text":"BLK-02 old-contract probe"}

-> HTTP 200
-> {"ok":true,"path":"C:\\Users\\PC\\.dsh\\profiles\\desktop\\blk02-probe-old.txt","size":25}
```
- 期望落点（画布后期目录）：`<画布数据根>\projects\<项目id>\craft\`
- 实际落点：`C:\Users\PC\.dsh\profiles\desktop\`（= DSH 进程 cwd），**HTTP 200、无任何错误提示**
- 源码依据：`dsh-artcraft/index.js:193-200 resolveBaseRel(base, rel)`：无 `base` 时走 `resolveCallerPath(rel)`；`182-191` 中 `path.resolve(相对路径)` 直接按进程 cwd 解析，**不做「必须绝对路径」的校验**（该函数的报错分支只覆盖空值，`path.resolve` 永远返回绝对路径，所以永远不会抛错）→ 静默错位。

### P4 · 新契约写入：落点正确

```
POST http://127.0.0.1:3292/artcraft/api/fs
Content-Type: application/json
body: {"base":"D:\\Code\\deepseek-plugin\\_qa\\blk02-probe","path":"craft/probe.txt","text":"BLK-02 new-contract probe"}

-> HTTP 200
-> {"ok":true,"path":"D:\\Code\\deepseek-plugin\\_qa\\blk02-probe\\craft\\probe.txt","size":25}
```
即：`base=<项目绝对目录>` + `path=craft/…` 形状可用，落点可控。证据文件保留：`D:\Code\deepseek-plugin\_qa\blk02-probe\craft\probe.txt`（25 B）。

## 3. 建议验收判据（按 Chief 新口径改写）

1. **落点断言（主判据）**：任意一条同步/写回路径产生的文件，必须落在 `<画布数据根>\projects\<项目id>\craft\` 下；实际落点用返回体 `path` + `Test-Path` 双重确认。
2. **禁止静默错位**：旧 `rel=` 无 `base` 的调用必须**显式失败**（4xx/5xx 或可读错误），不得 200 写到进程 cwd；静默错位优先级高于"报错"修复。
3. `GET /artcraft/api/status` 不再被依赖：`rootMismatch` 若保留，数据来源改为画布自己算出的项目目录。
4. `docs/artcraft-handoff.md` 中不出现已废弃 `rel=`/`dataRoot` 契约描述，示例与实际配置一致。
5. 提测单给出实际 HTTP 调用与响应状态码（含落点 path）。
6. 回归时同时确认没有新增工作区外垃圾：本次探针残留 `C:\Users\PC\.dsh\profiles\desktop\blk02-probe-old.txt`（25 B，沙箱拒删，已记待清）。
