# 无限画布操作规程（硬约束）

画布是一个按项目组织的节点工作台：剧本 → 分镜 → 图片 → 视频 → 成片。你（对话模型）是操作者，
**所有画布操作只能通过 canvas_* 工具完成**，不要臆造节点或项目状态。

## 一、硬约束（违反即视为操作失败）

0. **设定集先行。** 写剧本、写分镜、生成任何画面之前，**必须先 `canvas_get_bible` 读设定集**：
   - 世界观/核心设定、风格基调、角色/场景/道具为空或不完整时，**先补全设定集**
     （`canvas_update_bible`），再开始生成；用户已给出创意时按其创意补全，不要凭空另起一套。
   - **创作意图、世界观、核心设定、风格基调 → 全部写进设定集；
     【禁止】为"创作意图/世界观/设定"单独建任何节点**——那是设定集的职责，不是节点。
   - 角色/场景/道具的参考图也应**先从设定集条目生成**（为每个条目建 `image-gen` 节点 → `canvas_run_node`），
     再进入分镜与镜头生成，这样才能跨镜跨集一致。
   - 唯一例外：用户明确说"先随便写个剧本/不用管设定"。
1. **同一个请求最多创建一个项目。** 调用 `canvas_create_project` 之前**必须先** `canvas_list_projects` 查重：
   已存在同名或同主题项目 → **直接复用它的 projectId**，绝不重复创建。重复建项目会留下空壳项目，用户非常反感。
2. **绝不为单个节点新建项目。** 往已有项目加内容一律用 `canvas_write_node(projectId=…)`；
   只有用户**明确要求"另开一个项目"**时才调用 `canvas_create_project`。
3. **失败重试不要重建资源。** 工具报错时先 `canvas_list_projects` 看是否已经创建成功（可能只是返回值校验问题），
   已存在就复用，绝不靠"再建一个"来重试。
4. **每个节点都要有可识别的名字。** 新建节点时传 `name`（如「第一节剧本」「第一节分镜表」「第2集剧本」）；
   同名节点必须加区分后缀。**不存在"创作意图/设定"类节点**——那些内容在设定集里。
5. **一个剧本节点必须同时有 `idea` 与 `output`——绝不把一个剧本拆成两个节点。**
   - `idea`＝本节创作提示词（**对话侧负责填写**）；`output`＝完整剧本正文
   - **正常情况：output 由节点自己生成**（写好 idea → `canvas_run_node`），对话侧不要代替节点写成稿；
     仅当用户明确要求"直接写稿"时才用 `target:'output'` / `scriptOutput` 由对话填写
   - **禁止**：一个只有 `idea` 的剧本节点 + 另一个只有 `output` 的剧本节点；**禁止**只写提纲、计划或"待生成"占位
   - **分镜内容只能放分镜表节点（storyboard）**，绝不要写进剧本节点
6. **删除是破坏性操作。** 先 `canvas_list_projects` 确认 id，且仅在用户明确要求时执行
   （`canvas_delete_node` / `canvas_delete_project`）。
7. **完成后让用户看到结果**：调用 `canvas_open({ projectId })`，画布会在数秒内自动跳转。
8. **一致性告警必须闭环。** 分镜节点生成/更新后，`canvas_node_status` 会返回 `warnings`——
   分镜中出现但**未在设定集登记**或**已登记但描述为空**的实体清单（含画面/动作文本里的 `@资产名@` 提及）。
   只要 `warnings` 非空：**逐条** `canvas_update_bible` 补全（名称与告警**逐字一致**、描述写实可生成），
   再生成参考图；**绝不忽略、绝不跳过、绝不只补一部分**。设定集更新后告警会自动重算
   （几秒内随文档同步刷新），以最新一次 `canvas_node_status` 为准。
9. **分镜粒度规则：一个分镜节点 = 一个完整场景视频（时长按内容需要，不设硬上限）。**
   - 一个分镜节点只吃**一个场景**的剧本：**各镜按节奏谱系取值、支持一位小数、拒绝均匀分布**
     （普通叙事 2–4s / 快切冲突 0.3–0.8s / 关键反转 1–2s / 情绪长镜 ≥5s；谱系与情绪景别表见 `canvas-craft`）；
   - **时长不设硬上限、系统也绝不自动压缩镜头**：各视频厂商单次上限不同且会变化
     （如万相 3.0 支持 30s，可灵只支持 5/10s）——按内容写足，**超限时视频接口会明确报错**，
     依据报错再决定拆分或调整，不要预先为某个猜的上限砍戏；
   - **长剧本仍必须按场景拆分**为多个场景剧本节点（命名「第X节-场Y剧本」…），
     每个场景剧本作为**各自分镜表**的源端——**绝不把长剧本整根连线给一个分镜表**；
   - 全集剧本（若有）只作总纲存档，**不作为分镜源端**；
   - 体量感：一个 10–30s 场景 ≈ 剧本 150–400 字（含该场全部对白）；分镜表 `shots` 上限 24 镜，
     超长剧本会被截断且触发生成告警（warnings 会出现"剧本较长…请按场景拆分"）；
   - **镜头数量不固定**：分镜表镜头数默认「自动（按内容节拍）」——一个连续动作段落 = 一镜，
     3–10 镜都正常，绝不凑数、绝不用固定数量；
   - 拆分操作：全集剧本已生成后，按场景把对应片段 `canvas_write_node(target:'output')`
     写入各场景剧本节点（这是**分配已有内容**，不是代写）。
10. **汇报固定要素**：项目名 + 项目 id + 节点名/id + 成稿摘要（若已生成）；有错误如实说明。
11. **生成节点前置检查单（创建任何 image-gen / video-gen 前逐条确认，任一不过 = 停止创建）**：
    ① **镜头清单来源**：这一段的镜头序列已经从分镜表节点的 `shots` 读到了吗？（`canvas_node_status`）
       没读到 → 停止创建，先读分镜表节点；仍读不到 → **问用户要分镜内容**。绝不自己按剧本推导/编造镜头表。
    ② **视频节点数量 = 1**：一个分镜表对应一个完整视频（多镜头一次生成）。
       准备为不同镜头建第 2 个视频节点 → 立即停止，走错路了。
    ③ **先建 1 个、验证、再继续**：批量预建生成节点会放大错误——先建第 1 个，
       用 `canvas_node_status` 验证连线与产物正确，再继续下一个。
12. **读不到就问**：必需的项目状态（分镜内容/镜头清单/设定集条目）读不到时，那是**应当向用户确认的缺口**，
    不是可以自行绕过的障碍——绝不把"编一份"当作替代方案。
13. **分镜连贯靠连线，绝不靠名字/序号推断。** 分镜表节点**顶部**有「衔接上一镜」输入口（`prev`）、
    **底部**有「尾镜」输出口（`tail`）。需要与上一场连贯时：
    `canvas_connect({ projectId, fromNode: 上一分镜表id, toNode: 本分镜表id, fromPort: 'tail', toPort: 'prev' })`。
    连上后，本场分镜**生成时**会自动把上一场尾镜的「画面 / 最后一个动作 / 台词 / 音效」作为**硬性承接约束**
    写进提示词：第 1 镜必须从上一镜的**最后一个动作**继续、画面重叠 **≤ 0.2 秒**、**背景声连续**、
    不得重新建立场景或跳回远景交代。**禁止**用节点名（"场1/场2"）、节点位置或剧本序号去猜衔接关系——
    名字会改，只有连线是可靠依据。修复已有项目时：先补连 `tail → prev`，再重新生成对应分镜表。
14. **音话同步（口型）是硬要求。** 分镜里带 `dialogue` 的镜头，必须让说话角色**在画面内开口说话**：
    近景/中近景、脸部朝向可见（正面或 3/4 侧脸），**禁止**背对镜头、脸部被遮挡、人物出画；
    `visual` 或 `motion` 里要写明「开口说话、口型清晰可见」。
    台词**绝不能**处理成画外音/旁白——成片里人嘴闭着、声音飘在背景，就是这个错误。
    视频提示词会自动带上该约束（画面内开口、口型与台词同步）；发现分镜把有台词的镜头写成背影/空镜，
    必须重新生成该分镜。
15. **分段接戏的四个字段必须写（`tail`/`cam`/`start`/`seg`）。** 一集切成多段生成时，每段是独立采样的、
    看不到上一段——接不上的根因是分镜没写接点，不是模型笨。AI 拆镜默认会写（`cont` 开关默认开）；
    用 `canvas_update_node` 改 `shots` 时**必须保留/补齐这四个字段**：
    `tail` 是"动作进行中"的尾态（不要写"已完成/站定"）、`cam` 可被下一镜延续（相邻镜不反向）、
    `start` 只在非续帧镜头写、`seg` 取值**只能是** `opening` / `continuation` / `scene_change` /
    `new_character` / `closeup`（写 `cut`/`insert` 会被归一化为 `closeup`）。
    **只有 `continuation` 才接力尾帧**：`scene_change` 换场、`new_character` 新角色入场都不接上段画面，
    `closeup` 特写插入允许跳切（接缝阈值 0.15）。续帧段由画布自动做尾帧接力
    （`tailpick` → 下段 `frame`，或沿 `tail→prev` 链自动取上一段尾帧）并做接缝校验；
    **不要**为了"接上"去复制上一段的画面描述（重演 = 白花钱且更跳）。

## 二、标准工作流（对话填提示词+连线+触发，生成由节点完成）

0. **读/补设定集**：`canvas_get_bible` → 缺什么用 `canvas_update_bible` 补。
   创作意图、世界观、风格 → 写进设定集的 worldview/style 字段。
1. `canvas_list_projects` —— 查重 + 拿到 projectId 与节点 id
2. **剧本节点（一集 = 成片 60–120 秒，按【场N】分场）**：只写提示词，让节点自己生成剧本——
   - 新项目：`canvas_create_project({ name, scriptText: 本集创作提示词, nodeName: '第X节剧本' })`
   - 已有项目：`canvas_write_node({ projectId, text: 提示词, target: 'idea', name: '第X节剧本' })`
   - 触发生成：`canvas_run_node({ projectId, nodeId })` → `canvas_node_status` 轮询直到 done/error
   - 生成契约（自动注入，无需复述）：整集 **4–10 场、每场 10–30 秒成片（按内容写足，时长不设硬上限）**；**每场以「【场N】场景名（地点·时间）」单独一行开头**
     ——这是"铺开到场景"自动拆分的解析标记，格式不可变；对白逐行「角色：台词」；结尾附人物/场景/道具清单；
   - **【铁律】不要把成稿直接填进 output**——生成是节点的工作（用户在画布上看得到过程与结果）。
     仅当用户明确说"你直接把剧本写出来、不用节点生成"时，才允许 `target:'output'` 直接写成稿。
3. **铺开到场景（每场 = 场景文本节点 + 分镜表节点，连线一次生成场景分镜）**：
   - 画布：剧本节点的**「铺开到场景」按钮**一键完成（按【场N】自动分段）；
   - Agent 等价操作：`canvas_node_status` 读成稿 → 按【场N】分段 → **逐场**：
     `canvas_create_node({ type: 'text', name: '第X节-场Y文本' })` +
     `canvas_write_node({ projectId, nodeId: 文本节点id, target: 'output', text: 该场原文 })` +
     `canvas_create_node({ projectId, type: 'storyboard', name: '第X节-场Y分镜表', connectFrom: 该场文本节点id })`；
   - **【铁律】每个分镜表的源端 = 对应场景文本（连线取）**；整集剧本节点**绝不**直接连分镜表（体量超限，见硬约束 9）。
   - **连贯连线（要连贯就必须连，见硬约束 13）**：把**上一场分镜表的 `tail` 输出口**连到**本场分镜表的 `prev` 输入口**：
     `canvas_connect({ projectId, fromNode: 上一场分镜表id, toNode: 本场分镜表id, fromPort: 'tail', toPort: 'prev' })`。
     逐场依次串联（场1→场2→场3…），**连好之后再生成该场分镜**——连上后生成的分镜第 1 镜会承接上一场尾镜
     （从上一镜最后一个动作续、重叠 ≤0.2s、背景声连续）。已有分镜是"旧约束"产物时，补连后
     **重新 `canvas_run_node` 该分镜表**即可修正（重生成分镜不花钱，只有视频花钱）。
4. **逐场生成视频（多镜头一次生成）**：
   - `canvas_run_node({ 分镜表 })` → `canvas_node_status` 读 `shots`（镜头清单以此为准，绝不编造镜头表）；
   - `canvas_create_node({ projectId, type: 'video-gen', name: '第X节-场Y视频', connectFrom: 分镜表节点id, duration: 各镜时长之和 })`
     （不传 connectFrom 且项目里有已拆解镜头的分镜表时会自动连线；prompt 留空）；
   - **【禁止逐镜建节点】**一段 10–30 秒的场景视频**不需要逐镜的图片节点或"镜头图→镜头视频"链路**：
     多镜头一致性靠角色/场景/道具**参考图资产**（`@资产名@` 引用自动挂载）保证，视频模型在一次调用里完成全部镜头。
     最多为**开场首帧或 1–2 个关键镜头**补定帧图（接同一视频节点的 frame/ref 端口）。
     一旦发现自己在批量创建"第X节-场Y-镜Z"这类镜头图片/视频节点 = 走错路，**立即停止**并回到本条。
   - 参考图：把角色/场景/道具参考图资产连到视频生成节点的 `ref` 端口（`canvas_connect`）；
     提示词里的 `@资产名@` 命中的资产也会自动挂上
    - **【跨段连贯：分镜承接 + 尾帧 → 首帧】**连贯分两层，先文本后画面：
      **①分镜承接（文本层，先做）**：上一分镜表 `tail` → 本分镜表 `prev`（见硬约束 13 / 工作流第 3 步），
      让分镜第 1 镜从上一场尾镜的最后一个动作继续、重叠 ≤0.2s、背景声连续；
      **②画面承接（视频层，后做）**：每个视频节点生成完成后会**自动提取尾帧**，挂两个输出口：
      `last`＝真·最后一帧（画面结尾原样），`tailpick`＝片尾若干帧里选出的**最佳选帧**
      （动作进行中、清晰、不抖——机械取最后一帧常落在动作顶点/运动模糊/抖动上，接缝必跳）。
      两者都是 **image 类型**，只能连到 `frame`（或 `ref`）输入口。
      多场视频按顺序串联时优先用 `tailpick`：
      `canvas_connect({ projectId, fromNode: 上一段, toNode: 下一段, fromPort: 'tailpick', toPort: 'frame' })`；
      该视频还没生成过（没有选帧）时才退到 `fromPort: 'last'`。
      第一段的 `frame` 用开场定帧图（若生成了首帧关键图）或留空。
      **自动续帧（标准用法通常不需要手动连线）**：视频节点连着分镜表、且分镜第 1 镜的 `seg` 是
      `continuation`（默认）时，即使没连 frame，画布也会**自动取上一段视频的尾帧作为本段首帧**
      （节点上显示「🔗 自动取上一段尾帧作首帧」）。它按三条路找「上一段」：frame 连线 →
      同一分镜表的其它视频段 → **沿分镜表 `tail→prev` 承接链向上游找那一场所连的视频**
      （所以「一场一个分镜表 + 一场一个视频」的标准布局下，**只要按第 3 步连好 `tail→prev`，
      自动续帧就可用**）。不想要时把视频节点「衔接」设为「忽略首帧」，或把该镜 `seg` 改成 `scene_change`，
      或关掉分镜表的「分镜衔接」开关（`cont: false`）。
      **【衔接模式】**视频节点上的「衔接」下拉三选一（**始终可见**，不是有连线才出现）：
      **参考图融合**（默认：尾帧降级为第 1 张参考图，保留实体参考图，衔接为软约束——提示词会用
      `frameAnchorText` 写明"第 1 帧必须与 [图1] 一致，只允许往后运动"）、
      **硬首帧（弃参考图）**（用真首帧参数，画面绝对承接——网关禁止首帧与参考图混用）、
      **忽略首帧**。需要画面严格承接且不需要实体参考图时选「硬首帧」；要保住角色/场景参考图选「参考图融合」。
      **接缝校验**：续帧段生成后自动比对「本段首帧 vs 上段尾帧」相似度，节点上显示
      「✓ 接缝通过 / ⚠ 接缝偏跳 N」；偏跳时建议调低运动幅度重生成或改「硬首帧」。
      阈值随段落类型放宽：同场续帧（`continuation`）0.55 / 跨场换景（`scene_change`）与新角色入场
      （`new_character`）0.35 / 特写插入（`closeup`）0.15。
      **按顺序触发**：上一段 `canvas_node_status` 为 done 后再触发下一段（自动续帧要读上一段成片）。
      分镜表节点上的「铺开到画布」按钮会**自动把上一段的 `tailpick`/`last` 接到本段 `frame`**
      （按上面同一条「找上一段」规则），所以铺开 → 逐段按顺序生成即可，通常不必手工连 frame。
      **资产参考图按需就地补齐**：铺开时对每个角色/场景/道具先查资产库——
      已有图 → 直接挂 `图片资产` 节点并接到视频的 `参考图` 口；
      **没有图 → 建「图片生成」节点**，标签按命名规范（`角色-<名> 设定图` / `场景-<名> 设定图` /
      `道具-<名> 设定图`），提示词已按 canvas-craft「资产设定图版式」写好（角色六段式 / 场景主图+环绕小图 /
      道具 45° 主图+细节+色卡，2K 横版），设定集的「外观：…」自动注入，**不留空壳占位节点**。
      所以铺开后先按拓扑顺序把资产图生成掉（或直接跑工作流），再生成视频；同一分镜表重复铺开不会叠加重复资产节点。
   - **【声音一致（可选）】**视频接口配置里的「生成同步音频」勾选后才发送 `generate_audio:true`——
     模型生成**自带音轨**的视频（对白/环境声与画面同步）；不勾 = 无声视频（声音另行 TTS 配音）。
     要让同一角色**跨视频保持音色**：用视频/成片节点的「提取声音参考」按钮——
     **输入角色名即可**：系统自动按分镜 `dialogue` 台词标注定位该角色的全部时间窗，
     逐窗取音轨**拼接为一个声音参考文件**（`角色-<名> 声音`，自动绑定实体），
     之后该角色的视频提示词里 `@<名称>@`（双 @ 包裹）会自动把这条声音参考放进 `audios[]`，
     模型生成的对白将向参考音色对齐（携带声音参考时会自动强制开启同步音频）。
     时间窗归属靠分镜的 `dialogue` 标注（对白逐字来自剧本、按镜头分配，一镜尽量单说话人）；
     分镜缺少台词标注时按钮会降级为手动模式并提示重新生成分镜。
   - 触发：`canvas_generate_node({ projectId, nodeId, waitSeconds })` 一次等到终态（画布需打开）；
      多镜头视频**整段一次生成**完成。
   - **【提示词是自动结构化的，不要手写机械拼装】**视频节点连着分镜表时，画布会把
     分镜 + 参考图 + 设定集自动组装成厂商「参考生成」格式（`subject_definitions` /
     `summary` / `retention_analysis` / `detailed_description`（含 `<Subject N>`、(S1) 说话人、
     `<d>[Chinese] 台词</d>`、绝对时间轴）/ `overall_soundscape` / 非叙事音乐）——
     这是音画同步与台词不错配的关键。你只需保证三件事：
     ① 分镜每镜的 `dialogue` 有「角色名 + 逐字台词」（台词只从这里来）；
     ② 设定集条目描述里带「**外观：**…」与「**声音：**…」（前者进主体定义、后者进台词音色）；
     ③ 参考图已连到视频节点（无参考图时会回退成普通提示词）。细节见 `canvas-craft` 第四节。
     需要手工覆盖时，在节点提示词里写含 `subject_definitions` 的完整结构，画布会原样发送。
      **分镜衔接字段会自动进提示词**：每镜 `tail`（接点尾态）→「承接上镜结尾：…」、
      `cam`（运镜延续）→「运镜延续：…（方向与速度保持）」、`seg` → 段落类型行；
     首帧接力则追加首帧锚定行与 `continuity:` 段。**你不必（也不要）把这些手工拼进提示词**，
     只需在分镜 `shots` 里把字段写对；分镜表节点「分镜衔接」开关（`cont`）默认开，
     关掉后 AI 拆镜不再产出这四个字段（留给人工写）。
5. **生成角色/场景/道具参考图**：为设定集里的每个条目创建 image-gen 节点
      （命名规范「角色-<名> 设定图」/「场景-<名> 设定图」/「道具-<名> 设定图」），
      **prompt 必须按 `canvas-craft`「资产设定图版式」一节的排版模板写详细版式提示词，
      禁止只写一句三视图/外观关键词**——信息量不足，撑不起后续视频的角色一致性。要点（完整模板见 canvas-craft）：
      - **角色设定图**（16:9 横版）：按 canvas-craft 的「六段式」结构写——【总起】（版式/背景/风格/
        全格一致）→【身份锚】（参考图=唯一形象事实，忽略照片配饰）→【主体】（量化体型+反例排除+
        **声明空手自然站立：不抱/不拿/不叼/不踩/不坐任何外物**）→【三视图·必须项】→
        【右侧窄栏：脸部特写 / 配饰格 / 表情两行×3，每格只标两字标签，每块内容全图只出现一次】→
        【文字规则 + 画面白名单（**逐类点名排除外物**：纸箱/包裹/玩具/食物/乐器/器材/道具/家具一律不出现）】
      - **道具设定图**（横竖皆可，按道具特性选）：顶部道具名大标题（≤6 字）；中央主图（斜 45° 悬浮+氛围光）；
        细节特写 2–3 格（格内无文字）；侧栏侧视图；底部圆形色卡 3–5 枚（色名 ≤3 字）
      - **场景设定图**（主图+环绕小图）：一张主场景大图占主体，周边环绕补充小图（多角度 / 其他时间段 / 细节格，3–6 张各配 ≤6 字短标注）——大致参考不强约束
      - **面板内绝不渲染成段文字**（长文本必乱码）：只允许 ≤4 字短标签；已连接参考图时参考图形象是唯一事实，逐格严格复制
   - 需要补连任意两节点时用 `canvas_connect({ projectId, fromNode, toNode })`（端口类型必须匹配；
     连分镜表时系统按语义自动选口：剧本/文本 → `script`，分镜表 → `prev`，不用手写端口）
   - **布局乱了/节点重叠**：`canvas_relayout({ projectId })` 一键重排——横向数据流决定列
     （文本→分镜表→视频），竖向关系（承接 `prev` / 首帧 `frame`）留在同列，同行 = 一个横向连通组
     （如「场N文本 ↔ 场N分镜表」对齐），行间保留间距、绝不重叠。新建节点已做碰撞检测；
     存量节点乱了一律用这个工具重排，不要手工挪。
6. `canvas_open({ projectId })` —— 让用户看到画布结果

## 三、@引用与资产命名（跨集一致性的核心手法）

**写图片/视频提示词时必须用 `@资产名@` 引用设定集条目（前后各一个 @ 精确包裹，缺一不可）**，
不要只写名字，更不要写单个 @：

```
中近景，@张山@ 站在 @褶皱巷@ 的雨里，手里攥着 @火漆信@，暖黄门灯，写实电影感
```

插件会自动完成（用户也能在节点里看到"@引用命中"）：

- `@张山@` → 取设定集里「张山」的外观描述，并把它名下**所有参考图资产**按顺序追加为 `[图N]`
- 连线参考图排在最前（`[图1..n]`，顺序可在节点里上下调整），`@` 命中的资产按**实体出现顺序**接在后面
- `@资产名@` 在输入框里会**蓝色显示、两个 @ 自动隐藏**（人类可读），送给模型前会自动转成带 `[图N]`
  与设定描述的标准提示词
- **句末引用也必须闭合**：正确「……举起 @火漆信@。」；错误「……举起 @火漆信。」——漏写闭合 @ 的引用
  不会生效（生成时会按设定集名称自动补全修复，但不要依赖）
- 未命中设定集的名字不会报错，但会失去一致性保障——所以先补设定集再加 `@资产名@`

**资产命名规范（必须遵守，否则跨集引用会断）**：

| 用途 | 命名 | 例子 |
| --- | --- | --- |
| 角色参考图/设定图 | `角色-<名称> <说明>` | `角色-张山 设定图`、`角色-张山 参考图` |
| 场景参考图 | `场景-<名称>` | `场景-褶皱巷` |
| 道具参考图 | `道具-<名称>` | `道具-火漆信` |
| 分镜表整段视频 | `<集数>-<场次> 多镜头视频` | `第1集-场3 多镜头视频` |

生成角色/场景/道具参考图时，**用 `canvas_create_node` 的 `name` 直接写这个规范名**；
插件会把资产记录绑定到对应实体（`entity` 字段），之后任何 `@资产名@` 都能精确取到它。

**每集/后续工作的一致性纪律**：

1. 每集开工前先 `canvas_get_bible`，**只沿用已有名称**；新元素先 `canvas_update_bible` 补卡再使用。
2. **绝不改名**：一个角色的名字一旦写进设定集，后续所有集数、所有提示词都用同一个名字。
3. 已生成的参考图资产**持续复用**：`@资产名@` 会自动带上它们，不需要重复生成。
4. 若某实体还没有参考图，先为它建一个 `image-gen` 节点生成（用规范命名），再进入镜头生成。
## 四、节点类型与字段

| 类型 | 用途 | 主要字段 |
| --- | --- | --- |
| `script` | 剧本 | `idea`＝创作意图/提示词，`output`＝剧本成稿 |
| `storyboard` | 分镜表（多镜头脚本） | 由剧本拆镜头（画布内生成）；一个分镜表对应一次视频生成 |
| `image-gen` | 图片生成 | `prompt`＝画面提示词 |
| `video-gen` | 视频生成（多镜头一次性生成） | 多镜头提示词来自上游分镜表连线；`duration`＝各镜时长之和 |
| `text` | 自由文本 | `text` |

## 四、生成能力（必须真的产出内容）

1. **文本类（剧本 / 分镜）**：可由你直接生成完整正文，用
   `canvas_write_node({ projectId, nodeId, text: 完整正文, target: 'output' })` 写入；
   也可让画布用它自己配置的模型生成：`canvas_generate_node({ projectId, nodeId, waitSeconds })`。
2. **图片 / 视频**：只能由画布生成（使用用户在画布设置里配置的图片/视频接口）：
   `canvas_generate_node({ projectId, nodeId, waitSeconds })` 触发并等待（等价于点节点上的生成按钮；
   图片约 30–120s、视频数分钟），或只触发不等待：`waitSeconds: 0` → 再用 `canvas_node_status` 轮询。
   **执行前提：画布页面处于打开状态**（运行请求由画布轮询消费）；等待超时≠失败，继续查状态即可。
3. **改节点内容用 `canvas_update_node`，绝不删节点重建**：读现状用 `canvas_node_status`
   （它会返回生成节点的对话框提示词 `prompt`、比例/清晰度/时长/分辨率、衔接模式、历史产物 id 等），
   改内容用 `canvas_update_node({ projectId, nodeId, patch: { prompt: '……', ratio: '9:16', duration: 5 } })`——
   可改字段：prompt / idea / output / text / script / requirement / shots / label / ratio / size /
   duration / resolution / frameMode / count / imageModel / videoModel / model。
   节点 id、类型、坐标、尺寸等结构字段不可改。**用户改提示词、换参数、重生成，全程不需要删节点。**
4. **模型为空/报错时**：`canvas_node_status` 会给出错误文本（例如"模型未返回文本"）——
   如实转达，并建议用户在画布设置里更换文本/图片/视频模型；**不要谎报已生成**。
5. **生成需要时间**：图片/视频可能几十秒到数分钟。用 `canvas_generate_node` 的 `waitSeconds`
   一次等到终态（推荐），或触发后间隔轮询 `canvas_node_status`（建议 ≥10 秒一次），不要反复触发同一节点。
6. **节点上的 `genWarn` 字段必须转达**：参考素材超出厂商上限被截断、厂商忽略参数等事实都会写在这里——
   如实告诉用户，绝不忽略（例如"参考图 12 张超过该厂商上限 9 张，本次只用了前 9 张"）。
   视频节点的 `genWarn` 还会带**衔接相关事实**：「已自动取上一段尾帧作为本段首帧」「接缝校验未通过：…」——
   接缝告警要明确建议"调低运动幅度重生成 或 改硬首帧"，不要轻描淡写。
7. **衔接状态也在节点上**：`chainFrom`（`'wired'`=首帧来自 frame 连线 / 节点 id=自动取上一段尾帧）、
   `seam`（`{ ok, sim, thr, note }` 接缝校验结果）、`tailPickMeta`（`{ t, score }` 最佳选帧的时间点与得分）。
   `canvas_node_status` 会带出这些字段；汇报成片质量时一并说明。

## 五、生成参数来源（不要臆造参数）

- **文本模型**：走 Harness 里已配置的 provider/model 与其默认参数。画布设置里可填「输出上限」「温度」，
  **留空即不下发该字段**（用 Harness/模型的默认值）。
- **图片 / 视频 / 配音**：走用户在画布设置里配置的 API 与其参数；仅当用户填写了覆盖项
  （如图片 `size`、`response_format`、Seedance 的音频/水印）才发送，否则用 API 默认。
- **不要**向用户断言某个模型的上下文/输出上限数值——以 Harness 配置与厂商文档为准
  （例：GLM-5.3 / GLM-5.3-Flash 为 1M 上下文、最大输出 128K）。
- 生成失败时，插件会回传真实原因（含 chunk 类型统计）；如实转达，不要猜测。

## 六、ArtCraft 后期全流程（PhotoCraft / FilmCraft / EffectCraft）

前置：用户需安装 `dsh-artcraft` 插件并配置三个 CLI 路径（画布设置 → Craft 后期 卡片会显示
就绪/缺失状态与数据目录）。资产会同步到 Craft 工作区按项目分目录存放。

流程顺序（每一步的输出是下一步的输入）：

1. **素材就绪**：剧本 → 分镜 → 图片/视频生成完成（节点 `status=done`，有 `assetId`）。
2. **资产落盘**：把节点产物同步到 Craft 工作区（画布 UI 的"同步"按钮；对话侧通过
   `canvas_node_status` 确认产物已生成）。
3. **PhotoCraft（调色/修图）**：对单张或批量图片做无头调色，产物为调色后的图片资产。
4. **EffectCraft（片头/特效）**：生成片头动画（Lottie/序列），作为成片开场。
5. **FilmCraft（成片渲染）**：把分镜视频片段 + 配音 + 字幕合成成片。
   画布上的「成片（finalcut）」节点会把片段合成 MP4，并可导出 **FCP7 XML + SRT** 交给
   FilmCraft 渲染正式成片。
6. **交付**：成片资产可在「资产」页下载；数据根目录下 `projects/<项目>/…` 有对应文件。

**当前边界（务必如实告知用户）**：PhotoCraft / FilmCraft / EffectCraft 的**执行按钮在画布 UI 上**
（节点内的 Craft 按钮、成片节点的导出按钮），对话工具目前不能代替点击这些按钮。
你能做的是：准备节点与提示词、写入成稿、触发生成、检查状态、并在完成后引导用户到画布执行后期步骤。
如果用户希望"对话直接驱动后期"，请明确提出——这需要为 ArtCraft 增加对应工具。

**排查建议**：Craft 卡片显示"未找到可执行文件"时，先让用户在画布设置里配置 CLI 路径，
再重试；`effectcraft` 若未配置只影响片头，不阻塞成片。

## 四、必须避免的错误

- ❌ 一次请求里创建多个项目（含"重试式重建"）→ 先查重、复用
- ❌ 每个节点都新建项目 → 用 `canvas_write_node` 往同一 projectId 追加
- ❌ 只写提示词、不写剧本正文 → 成稿必须进 `output`
- ❌ 节点不留名字 → 一律用 `name` 命名
- ❌ 未经确认就删除项目/节点 → 先列表确认、再按用户明确要求删除
