## 0. 定性更正（必须读）

PM 首测曾把 `GET /artcraft/api/fs?op=list&rel=projects` 的 400 读成「`rel=` 参数面已不存在、被 400 挡住」——**该定性错误**。
QA 打活端点复核证明：`rel=` **仍被接受**，真正的缺陷是**解析基准 = 插件进程 cwd**，写入**HTTP 200 静默成功但落到错误目录**；那个 400 只是 cwd 下找不到 `projects` 的 ENOENT。

## 1. 根因（代码级，PM 与 QA 双向核对）

- `dsh-artcraft/index.js:193-200 resolveBaseRel(base, rel)`：无 `base` 时走 `resolveCallerPath(rel)`。
- `dsh-artcraft/index.js:182-191 resolveCallerPath(s)`：`const abs = path.resolve(s)` → **恒返回绝对路径** ⇒ `187` 行 `if (!path.isAbsolute(abs))` 的「需要绝对路径」守卫**永远不触发**（死代码）。
- 于是相对路径被按 **DSH 插件进程 cwd**（`C:\Users\PC\.dsh\profiles\desktop\`）解析。
- 画布调用方传的正是**相对路径**：`client.js:4554/8660/8661`；调用形状 `client.js:4482-4485`。

## 2. 实测（QA 探针原文，详见证据文件）

| 探针 | 结果 |
|---|---|
| `POST /fs?action=write&rel=blk02-probe-old.txt`（画布现用形状，JSON `{rel,text}`，无 `base`） | **HTTP 200** `{"ok":true,"path":"C:\\Users\\PC\\.dsh\\profiles\\desktop\\blk02-probe-old.txt","size":25}` —— **静默错位，零报错** |
| `GET /fs?op=list&rel=projects` | HTTP 400（cwd 下无 `projects`）；`?op=list&path=D:/data/canvas-data/projects` → 200 |
| `?op=readtext&rel=…` / `/file?rel=…` | 同 cwd 基准；读不到即 400 |
| `POST /fs` `{"base":"<项目绝对目录>","path":"craft/probe.txt"}` | HTTP 200，落点正确 `_qa\blk02-probe\craft\probe.txt` |
| `GET /status` | **无 `dataRoot` 字段** → 调用方 `client.js:9898` 恒读空串，`rootMismatch`（9899）恒 false，「ArtCraft 数据目录与画布数据根不一致」提醒**永不触发** |

## 3. 期望 vs 实际

| | 内容 |
|---|---|
| 期望 | 画布发起的同步/写回落在 `<画布数据根>\projects\<项目id>\craft\` 下；地址契约错误时**显式失败** |
| 实际 | 200 成功，文件落在 DSH profile 目录（进程 cwd），用户以为同步成功；读回同类调用又 400 |

## 4. 影响面

1. **数据静默错位**：PhotoCraft/FilmCraft 的输入（`timeline.xml`/`subs.srt`/`grade.json`/媒体）写到 `C:\Users\PC\.dsh\profiles\desktop\` 下，不在项目目录 → 后期链路整体不可用，且用户无从察觉。
2. **磁盘污染**：DSH profile 目录被写入项目资产（视频可达数十 MB/条），无任何界面入口可清。
3. **读回失败**：`readText`/`file` 同基准 → 400，错误信息指向"请求错误"而非"路径基准错误"，误导排查方向。
4. **界面误导**：`rootMismatch` 提示永不触发，设置页不会提示数据目录不一致。
5. **文档失真**：`dsh-infinite_canvas/docs/artcraft-handoff.md` 整篇以 `dataRoot` + `rel=` 为前提，照着它开发会继续踩同一个坑。

## 5. 建议修复

- **调用方（`dsh-infinite_canvas`，主要修复）**：craft 段改为 `base=<项目绝对目录>` + `path=craft/…` 契约（实测可用）；`rootMismatch` 的数据来源改为画布自己算出的项目目录；同步重写 `docs/artcraft-handoff.md`。
- **被调方（`dsh-artcraft`，待评估）**：让「无 `base` 的相对路径」**显式失败**（可读错误），别再默默按 cwd 解析——避免下一个调用方重犯；即修 `resolveCallerPath` 里那条死守卫。
- 失败不得静默：写失败/落点异常要在返回体里带原因。

## 6. 回归判据（按 QA 新口径，缺一不算通过）

1. **落点断言（主判据）**：任意同步/写回路径产生的文件必须落在 `<画布数据根>\projects\<项目id>\craft\` 下；用返回体 `path` + `Test-Path` 双重确认。
2. **禁止静默错位**：旧 `rel=` 无 `base` 的调用必须**显式失败**（4xx/5xx 或可读错误），不得 200 写到进程 cwd；此项**优先于"报错可读性"**。
3. `GET /artcraft/api/status` 不再被依赖；`rootMismatch` 若保留，数据来源改为画布自算目录。
4. `docs/artcraft-handoff.md` 不出现已废弃 `rel=`/`dataRoot` 契约描述，示例与实际配置一致。
5. 提测单给出实际 HTTP 调用与响应状态码（含落点 `path`）。
6. 回归时确认未新增工作区外垃圾（现有残留见下）。
