## 6. 影响面判断

1. **磁盘垃圾累积**：每删一个项目就永久留下一份完整资产镜像（本项目 1 张 1K 图即 700 KB+，正常项目为几十 MB 级）→ 长期使用无上限增长，用户看不到也无法从界面清理。
2. **同名项目/重新导入污染**：若重新创建同名或同 id 项目，旧 `projects\<id>\` 未清空，存在读到陈旧文件的风险（是否按 id 复用目录需开发确认；本轮只验证到目录未删，未构造同名复用场景）。
3. **SQLite 与文件镜像不一致**：DB 行已删、CAS（`objects\`）本就不存在、镜像文件留存 → 三处状态不收敛；`assets.json` 已由删除路径同步清理，但磁盘目录没有对应动作。
4. **删除项目不做二次校验**：删除接口返回 ok 完全无法反映磁盘侧是否干净，界面/对话层都拿不到「还有垃圾」的信号。

## 7. 建议的修复与验证方式（修复后 QA 这样验才算真干净）

修复建议：`projectsDelete()` 的 SQL 分支中，删除 DB 行后同样调用 `removeDataRootProject(id)`（或按 rel 收集并删除本项目镜像文件），失败要可见（日志/返回字段），不要静默吞掉。

验证判据（缺一不算通过）：
1. 删除前记录 `projects\<id>\` 文件数与字节数 → 删除后该目录**不存在**（或为空目录）。
2. 全量 `projects\` 目录清单与删除前相比只少该目录，其他项目文件数/字节数不变。
3. CAS/objects 与 DB 无悬挂引用：`objects\` 不存在或删后无本项目对象；DB `assets`/`projects` 无该 id 残留行。
4. 重新创建同名项目 → 不读取到旧项目文件（新项目目录内只含本次新产物）。
5. 删除后重复删一次 → 幂等成功、无报错、无残留。
6. 界面侧：删除项目后磁盘检查纳入每轮回归的固定项（本轮起已在测试清单模板里固化）。

### 7.1 追加判据（PM / Chief 要求，2026-10-19）

7. **FTS 残留（已实测复现）**：删除项目后 `assets_fts` 搜索不应再命中已删项目的资产 name/prompt。`assets_fts` 是手动维护的，SQL 分支的 `DELETE FROM assets` 绕过了 `dbAssetDelete()`（402-411 行，那里才同步删 FTS），会漏。
   - 实测（只读探针 `docs/evidence/blk01-fts-probe.mjs`，node v24 `node:sqlite` readOnly）：`projects` 表已无 pmvex3446bnns、`assets` 表该项目 0 行，但 `assets_fts` 仍命中 2 条孤儿行：`a_mvex3p1wx2oac`、`a_mvex4pru513uh`（分镜 + 图片）；库内合计 **assets 56 行 vs assets_fts 58 行**，差 2 即本项目。
   - `MATCH 'QA冒烟'` 与 `MATCH '便利店'` 均命中上述 2 条 → 用户搜索会搜到已删项目的资产。
8. **两条删除入口都要覆盖**：`index.js:1174-1190 projectsDelete()` 与 `1696-1711 canvasDeleteProject()` 的 SQL 分支（两处都按同一方式清理镜像目录 + FTS）。
9. **`removeDataRootProject` 静默跳过场景**：`index.js:697-705` 在 meta 无 `folder` 条目时**静默 return、不删目录**。回归必须专门构造「SQL 模式下目录名 = 项目 id」（meta 里没有 folder 映射）的场景，确认修复后目录仍被删掉，而不是"看起来修了、这个分支没走到"。

10. **FTS 表级等值断言（比抽样命中更强，Chief/PM 追加）**：删除项目后必须满足 `COUNT(*) FROM assets_fts == COUNT(*) FROM assets`，并落成回归脚本 `test-delete-project.mjs`。
    - **执行口径（PM 2026-10-19 更正 + QA 澄清）**：存量孤儿（库内 58 vs 56，属已删项目 `pmvex3446bnns`）**不回溯清理、不算本单失败项**（另立 backlog **IC-B4**）；本判据取「**Δassets_fts == Δassets**（删除使两表同步减少相同行数）+ 本项目 FTS 0 残留」。**全局绝对等值在存量孤儿存在时不可能成立**（实测 61 vs 56），故不按全局绝对等值判失败。

### 7.2 本单验收范围（明确排除项）

- **本单范围 = 资产镜像目录（`projects\<id>\`）+ FTS 索引 + 僵尸文件；不含 `craft\` 目录。**
- `craft\` 目录**清理**独立成 backlog 卡 **IC-B2**，**不属 BLK-02**（BLK-02 是「画布↔ArtCraft 契约静默错位」，两件事无关）。IC-B2 真因：目录名由客户端 `craftProjectSlug()`（`client.js:4511`）按**项目名**生成、**只存在 localStorage，Host 不知情**；且 Host 的 `sanitizeFolderName` 与客户端 `slugifyName` 规则不同，**Host 凭猜测去删目录会误删同名项目的产物**。评估顺序排在 **BLK-02 之后**（目录基准正在从 slug 改成 `<id>`）。
